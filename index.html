Saarthi Chrome Extension — Privacy Policy

Last updated: 23 October 2026
Applies to: Saarthi Chrome extension version 2.0.9 and its related authentication and command services.

Saarthi provides a browser assistant, a Chrome side panel, local browser tools, Google sign-in, and an invite-code path for authorized owner and tester accounts. Google sign-in supports local tools and displays account identity; backend account-status endpoints are not yet available. AI commands for Google accounts are unavailable while backend authorization and quotas are being completed. Owner-only connected-home features are separate.

1. Information Saarthi handles

Google and Supabase sign-in

When you choose Continue with Google, Chrome opens a Google sign-in flow managed through Supabase Auth. Supabase provides Saarthi with a user ID, email address, and available profile name. The extension displays your name or email in the side panel and uses the user ID to check account status. The extension temporarily holds a sign-in verifier and then a Supabase access token, refresh token, account details, and expiry information in Chrome extension session storage. It sends the access token to the Saarthi API on Railway when requesting account status; the currently deployed backend does not yet provide the account-status endpoints. The refresh token is sent to Supabase Auth to renew a session; it is not sent to Saarthi's AI endpoint.

Google and Supabase process information needed to authenticate you under their own services. Signing out of Saarthi clears its local Google session and requests a local-scope logout from Supabase. Signing out does not itself delete your Google or Supabase account, and an already issued access token may remain valid until it expires.

Legacy invite-code sign-in

Authorized owner and tester accounts may enter a private Saarthi access code. The extension sends that code over HTTPS to Saarthi's Railway-hosted API to validate the account and stores the code and returned owner/tester identity in Chrome extension session storage while signed in. That code is also sent as a bearer credential with authorized legacy AI requests. Invite codes are not converted into Google or Supabase sessions.

Commands, speech, tabs, and webpages

When an authorized owner or tester submits a typed or spoken AI command, the resulting text is sent to Saarthi's Railway-hosted API. The backend sends command text to TypeSafe to interpret the requested action and returns a result or browser command. A command may itself include a website address, video title, device name, or other details you provide. Google accounts do not currently get this billable AI command path.

Backend deployment logs may record the original command text, extracted queries, action and target confidence values, and HTTP request metadata. Spoken commands can therefore appear in logs as text transcripts. Commands and queries may contain personal information you include in them.

Voice input uses the browser's SpeechRecognition feature. The browser or its speech-service provider may process audio to produce a transcript; Saarthi receives and handles the resulting text. The extension does not save microphone audio as a recording. The browser or speech provider handles its own processing and retention.

Saarthi content scripts run on ordinary webpages to show the assistant and carry out requested page or media actions. Depending on the action, they can inspect the current page, tab URL and title, media controls, or supported Instagram Reel media information. Access to a page does not mean its entire contents are sent to Saarthi's backend. A command you submit can disclose content you include in it.

Local utilities and downloads

Calculator and Images to PDF process your input in Chrome; selected images are converted into a PDF in the extension, and Chrome saves the result to your chosen download location. Focus, clock, timers, alarms, site dark mode, and music-tab controls operate in the browser without calling Saarthi's AI backend. The speed test contacts Cloudflare's speed-test service and transfers test data to measure the connection. Local tool settings, timer state, site-theme choices, and display preferences can be stored on this browser.

When you request a supported Instagram Reel download, the extension obtains media information from the Instagram page in your browser and asks Chrome to download the media from its source. It does not copy your Instagram cookies to Saarthi's backend. Chrome and the media source handle the download request. Saarthi keeps temporary download status in extension session storage; the downloaded file remains wherever Chrome saves it until you remove it.

Connected-home features

Connected-home setup is currently available only to a legacy owner account, not to a Google account or legacy tester. If the owner connects SmartThings or Atomberg, the extension stores the supplied provider connection information in an encrypted vault on that browser. It temporarily uses connection information during a signed-in owner session to make authorized requests to the selected provider. Device names, status, and control requests are exchanged with that provider. A recent device-activity summary may also be stored locally for display. Disconnecting a provider removes its saved connection from the vault; signing out clears the active session but does not by itself erase the saved vault. Some owner commands that are not completed locally may use the legacy AI service described above. If server-side SmartThings control is enabled, Railway also sends authorized owner device requests to SmartThings.

2. Service providers and recipients

  • Google and Supabase: Google sign-in and Supabase Auth account/session information, including account identifiers and authentication tokens needed for sign-in and refresh.
  • Railway: hosts the Saarthi API and its deployment logs, which may contain command text, extracted queries, confidence values, and HTTP request metadata. It receives legacy invite-code validation requests and authorized command text; the extension also sends Google-account status requests bearing Supabase access tokens, although those endpoints are not yet available on the deployed backend. Requests also expose ordinary connection metadata, such as IP address and time, to hosting infrastructure.
  • TypeSafe: receives authorized legacy AI command text from the Saarthi backend to interpret the requested action. Google-user AI commands are currently disabled.
  • Cloudflare: receives speed-test requests and random test upload data when you run Speed Test.
  • SmartThings or Atomberg: if the legacy owner connects a provider, it receives the information required for device discovery, status, and requested control.
  • Browser and requested websites: Chrome handles extension storage, speech recognition, tabs, notifications, and downloads. Requested actions can contact sites such as YouTube or Instagram. Browser speech processing may involve the browser's speech-service provider.
  • GitHub Pages: hosts this policy page and receives ordinary website requests when you visit it.

Saarthi uses the information described here to provide requested functions, maintain authentication, secure the service, and operate it. Provider-side processing and retention follow the applicable service settings and provider policies.

3. Chrome permissions and website access

  • storage: session credentials and sign-in state; local preferences, timers, display state, and the encrypted owner home connection.
  • identity: opens Google/Supabase sign-in and derives the Chrome OAuth callback.
  • sidePanel: displays Saarthi beside the webpage.
  • tabs: finds and controls tabs and playable media for user-requested browser actions.
  • downloads: saves requested supported media. The Images to PDF tool also starts a Chrome download of the PDF it creates locally.
  • alarms and notifications: schedules focus, timer, or alarm events and shows completion notices.
  • Website access on ordinary pages: content scripts can run across websites to show the assistant, toggle site dark mode, and perform requested page actions. An Instagram-specific content script runs on Instagram pages for supported downloads. Chrome-protected pages may not support these functions.
  • Network hosts: the manifest permits the Saarthi API on Railway, Cloudflare Speed Test, and the SmartThings and Atomberg APIs. Supabase host access is requested when you initiate Google sign-in.

4. Storage, retention, and deletion

On your browser: Supabase tokens, the temporary sign-in verifier, and legacy invite-code session information are kept in Chrome extension session storage. The sign-in verifier is removed after the sign-in attempt. Saarthi logout removes its local session; a failed refresh removes the Google session. Chrome also clears extension session storage when the browser restarts or the extension is reloaded, disabled, or updated. Local preferences, alarm and timer state, recent device-activity display data, and the encrypted connected-home vault can remain in Chrome extension local storage until changed, disconnected where applicable, or cleared with extension data. Uninstalling the extension clears its extension storage, but downloaded files remain in Chrome's download location.

On Saarthi and provider services: The Saarthi backend can keep temporary request counts and command context during operation. Supabase Auth maintains a Google-linked account record after you sign out. Railway infrastructure, Supabase, TypeSafe, the browser's speech service, and connected-home providers may retain operational logs, authentication information, or command-related data according to their applicable service settings and policies. Saarthi does not set a single retention period for records held by all of these services. Local logout or uninstall does not delete records already held by them. Saarthi currently does not offer in-extension account deletion.

To request access to or deletion of personal information associated with your Saarthi account, email saarthi.explore@gmail.com. We will review your request, take reasonable steps to verify account ownership, and determine what information can be deleted from systems under our control. We will process applicable deletion requests in accordance with legal requirements. Certain records may need to be retained for security, legal, or operational reasons, and information held in service-provider logs or backups may be subject to separate retention periods. Never send passwords, one-time passcodes, invite codes, access tokens, or Google credentials to verify your identity.

5. Security and your choices

Extension requests to Supabase, Saarthi's API, Cloudflare, and connected-home providers use HTTPS. The owner home connection is encrypted before it is saved in the browser's local extension storage. Session credentials are not placed in Chrome sync storage. You can use the local tools without signing in, stop using voice input, log out, disconnect a home provider if you are the owner, clear extension data, or uninstall Saarthi. Avoid entering passwords or other sensitive information in AI commands or on pages where you do not want an assistant to operate.

Saarthi is a general browser productivity tool and is not designed for children.

6. Changes to this policy

We will update the date above when the policy changes. A future release that enables Google-user AI requests or changes account, provider, or retention practices requires an updated disclosure before that feature is made available.

7. Chrome Web Store Limited Use

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements. Data accessed through Chrome extension permissions will be used only to provide Saarthi's disclosed user-facing functions and related permitted operational purposes.

8. Contact

For privacy questions and account-data requests, email saarthi.explore@gmail.com.
